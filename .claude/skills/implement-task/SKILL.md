name: implement-task
description: Выполнить задачу из трекера MyTracker по её ID. Использовать, когда пользователь передаёт ID задачи или вызывает /implement-task. Также использовать, когда в сообщении есть ответ владельца на вопрос (продолжение задачи).
---

Аргумент: ID задачи (`$ARGUMENTS`). API трекера: `$TRACKER_API` (например, `http://localhost:3001/api`), токен: `$TRACKER_TOKEN`.

Все запросы к API делаются так:
`curl -s -H "Authorization: Bearer $TRACKER_TOKEN" -H "Content-Type: application/json" ...`

1. Получи задачу: `GET $TRACKER_API/tasks/$ARGUMENTS`. Прочитай `goal`, `acceptance`, `outOfScope`, `context` и все `comments`: там могут быть ответы владельца и доработки.
2. Проверь, что `goal` и `acceptance` заполнены и понятны. Если чего-то не хватает, задай вопрос (см. «Вопрос владельцу» ниже) и остановись.
3. Составь план из 3–7 шагов и сохрани его комментарием: `POST $TRACKER_API/tasks/$ARGUMENTS/comments` с полем `text`.
4. Реализуй только то, что описано в `acceptance`. Всё из `outOfScope` не трогай.
5. Напиши или обнови тесты для новой логики (Jest + Supertest для API, Vitest + Testing Library для UI).
6. Запусти `npm run lint` и `npm test`. Если есть ошибки, исправляй их, но не больше 3 попыток.
7. Сделай коммит с сообщением `task(<id>): <title>`. Запиши в комментарий краткий summary и список изменённых файлов.
8. Если какой-то критерий приёмки выполнить не удалось, напиши это явно в комментарии. Не помечай задачу как выполненную.
9. Никогда не пушь в `main` и не мержи ветки. Работай только в текущей ветке.

## Вопрос владельцу

Используй его, только если без ответа нельзя продолжить: неясно требование, есть два несовместимых варианта или нужен доступ, которого нет. Не спрашивай о мелочах, которые можно решить разумным выбором и описать в комментарии.

Порядок:
1. Если уже есть изменения, сделай коммит с сообщением `task(<id>): WIP, ожидание ответа`. Незакоммиченная работа не сохраняется.
2. Сформулируй один конкретный вопрос с вариантами, если они есть.
3. Отправь: `POST $TRACKER_API/tasks/$ARGUMENTS/question` с телом `{"text": "вопрос"}`.
4. Заверши работу сообщением «Нужен ответ владельца». Больше ничего не делай: задача сама перейдёт в статус «Нужен ответ», а ответ придёт в следующем запуске.

Когда в запуске пришёл ответ владельца, учти его, продолжай с того места, где остановился, и выполните шаги 4–9.
