---
name: implement-task
description: Выполнить задачу из трекера MyTracker по её ID. Использовать, когда пользователь передаёт ID задачи или вызывает /implement-task.
---

Аргумент: ID задачи (`$ARGUMENTS`). API трекера: `$TRACKER_API` (например, `http://localhost:3001/api`), токен: `$TRACKER_TOKEN`.

1. Получи задачу:
   `curl -s -H "Authorization: Bearer $TRACKER_TOKEN" $TRACKER_API/tasks/$ARGUMENTS`
2. Проверь, что `goal` и `acceptance` заполнены. Если нет, добавь комментарий через `POST $TRACKER_API/tasks/$ARGUMENTS/comments` с текстом `Не хватает описания: ...` и остановись.
3. Составь план из 3–7 шагов и сохрани его комментарием к задаче.
4. Реализуй только то, что описано в `acceptance`. Всё из `outOfScope` не трогай.
5. Напиши или обнови тесты для новой логики (Jest + Supertest для API, React Testing Library для UI, если он подключён).
6. Запусти `npm run lint` и `npm test`. Если есть ошибки, исправляй их, но не больше 3 попыток.
7. Сделай коммит с сообщением `task(<id>): <title>`. Запиши в комментарий к задаче краткий summary и список изменённых файлов.
8. Если какой-то критерий приёмки выполнить не удалось, напиши это явно в комментарии. Не помечай задачу как выполненную.
9. Никогда не пушь в `main` и не мержи ветки. Работай только в текущей ветке.
