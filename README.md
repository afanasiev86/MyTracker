# MyTracker

Личный таск-трекер для MERN-проектов. Задачи описываются в трекере (веб-интерфейс или Telegram), затем Claude Code выполняет их в отдельной git-ветке, а вы проверяете diff и мержите сами.

## Структура

```
server/          Express + Mongoose: API, модель Task, воркер запуска, Telegram-бот
client/          React + Vite: доска, форма задачи, карточка с diff и комментариями
shared/          правила статусов, общие для сервера и клиента
.claude/skills/  implement-task (выполнить задачу) и task-spec (описать задачу)
CLAUDE.md        правила стека для Claude Code
deploy/          шаблоны systemd, nginx и скрипт бэкапа для VPS
```

## Статусы

`backlog → ready → in_progress → review → done`, из `in_progress` также `failed`.
Статус «В работе» задаётся только запуском. Запуск возможен из «Готово к работе», «На проверке» (доработка) и «Ошибка».

## Локальный запуск

Требуется Node 20+ и MongoDB (можно через Docker).

```bash
docker compose up -d        # MongoDB на 127.0.0.1:27017
npm install
cp server/.env.example server/.env   # заполните значения
npm run dev
```

- Клиент: http://localhost:5173
- API: http://localhost:3001/api

Для запуска задач нужны репозитории проектов в `REPOS_DIR/<project>` с `origin/main`, установленный Claude Code и вход выполнен (`claude`, затем `/login`).

## CRM

Вкладки приложения: «Задачи», «Проекты», «Клиенты».

- **Клиент**: имя, компания, контакты, заметки, тип оплаты (почасовая или фиксированная) и ставка. Затраты на Claude по всем проектам клиента считаются автоматически.
- **Проект**: название, slug (код проекта и имя папки репозитория), клиент, статус, ссылка на репозиторий (с токеном GitHub из «Настроек» синхронизируется с GitHub: выбор из списка, автосоздание, архивация), основная ветка и флажок «Коммитить сразу в эту ветку» (иначе результат лежит в ветке `task/<id>` и вливается вручную), срок и сумма. Видны число задач, открытых задач и затраты.
- **Задача** относится к проекту, у неё есть приоритет и срок.

Задачи создаются только в существующих проектах. Slug нельзя менять, если в проекте уже есть задачи. Проект с задачами или клиент с проектами не удаляются.

## Вопросы от Claude

Если задача описана не полностью, Claude задаёт один вопрос и останавливается. Задача получает статус «Нужен ответ», вопрос приходит в Telegram и отображается в карточке. Ответить можно ответом на сообщение бота, командой `/answer <id> текст` или формой в карточке. После ответа Claude продолжает ту же сессию.

Если запуск закончился ошибкой, в карточке задачи есть кнопка «Попросить Claude исправить» (можно добавить подсказку), в Telegram под сообщением об ошибке такая же кнопка «Исправить». Claude получает причину сбоя и конец лога и продолжает работу в той же ветке.

Запуск можно остановить кнопкой «Отменить запуск». Запуск, который идёт дольше `RUN_TIMEOUT_MIN` минут, останавливается автоматически.

## Telegram Mini App

Тот же веб-интерфейс открывается внутри Telegram. Вход выполняется автоматически по подписи данных Telegram, пароль не нужен. Требования: HTTPS-домен и адрес Mini App в карточке «Telegram-бот» (или `TELEGRAM_MINIAPP_URL` в `server/.env`). Открыть можно кнопкой «Трекер» у бота или командой `/app`.

## Telegram-бот

Подключите бота в интерфейсе: вкладка «Настройки», карточка «Telegram-бот». Введите токен от @BotFather и свой числовой Telegram ID, нажмите «Сохранить и подключить». Сервер проверит токен, запустит бота без перезапуска и отправит вам сообщение. Токен хранится в базе в зашифрованном виде (ключ берётся из `JWT_SECRET`) и в интерфейсе после сохранения не показывается. Значения из интерфейса важнее `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID` в `server/.env`, которые по-прежнему работают. Команды:

- `/new <проект> <заголовок>`: создать задачу
- `/ready <id>`: перевести в «Готово к работе»
- `/run <id>`: запустить в Claude
- `/status`: активные задачи
- `/server`, `/logs <сервис> [строк]`, `/service <restart|start|stop> <сервис>`, `/deploy`: управление сервером (подробнее в `docs/RUNBOOK.md`, раздел 3c). То же во вкладке «Сервер»

Уведомления приходят при переходе задачи в «На проверке», «Ошибка» и при достижении лимита. Бот работает через long polling, поэтому webhook для этого бота задавать нельзя.

## Тесты и линтер

```bash
npm run lint
npm test                                  # без БД пропускаются тесты API
MONGO_URL_TEST=mongodb://127.0.0.1:27017/mytracker_test npm test   # полный набор
npm run build
```

В CI (`.github/workflows/ci.yml`) тесты запускаются с сервисом MongoDB.

## Развёртывание на VPS

1. Клонируйте трекер в `/srv/mytracker`, выполните `npm ci` и `npm run build`.
2. Скопируйте `server/.env.example` в `server/.env` и заполните значения. Файл доступен только владельцу: `chmod 600`.
3. Установите `deploy/mytracker-api.service` в systemd и включите его.
4. Настройте `deploy/nginx.conf` и HTTPS через certbot.
5. Добавьте `deploy/backup-mongo.sh` в cron.
6. Для push веток задач настройте deploy key с доступом на запись только к нужным репозиториям.

## Ограничения текущей версии

- Один пользователь, вход по паролю.
- Карточки можно перетаскивать между колонками и внутри колонки, но только по разрешённым переходам статусов: в «В работе» и «Нужен ответ» задача попадает только работой Claude. Кнопки в карточке остаются.
- Лимит подписки распознаётся по тексту вывода Claude Code. Формат сообщения может измениться, и тогда список шаблонов в `server/src/worker/limits.js` нужно дополнить.
- Тесты API с БД запускаются в CI, локально они пропускаются без `MONGO_URL_TEST`.
