# Вечерний запуск трекера: чеклист

Всё по порядку. Каждый шаг с проверкой. Если шаг не прошёл, переходите к разделу «Если что-то сломалось».

## 0. До вечера (с телефона, 2 минуты)

- [ ] Создан VPS (Ubuntu 22.04 или 24.04), есть root-доступ по SSH-ключу
- [ ] Есть домен или поддомен, направленный на IP сервера (нужен для Mini App; для первого теста через браузер можно обойтись без него)
- [ ] Есть Telegram-бот: создан через @BotFather, сохранён токен
- [ ] Узнан свой числовой Telegram ID (например, через @userinfobot)
- [ ] Есть подписка Claude Pro и доступ к Claude Code на сервере (вход по ссылке)
- [ ] Хотя бы один тестовый репозиторий на GitHub с веткой `main` (можно пустой проект с `README`)

## 1. Установка на сервер (≈15 минут)

```bash
ssh root@IP_СЕРВЕРА
apt-get install -y git   # если git нет
git clone -b init https://github.com/afanasiev86/MyTracker.git /tmp/mt
sudo bash /tmp/mt/deploy/bootstrap-vps.sh
```

Во время установки скрипт выведет **пароль для входа** (в разделе «Файл .env»). Сохраните его сразу.

Проверка:
- [ ] Последняя строка скрипта: `{"ok":true} <- API отвечает`
- [ ] `systemctl status mytracker-api` показывает `active (running)`

Если `bootstrap-vps.sh` упал, ошибка будет в последних строках. Скрипт можно запускать повторно: он пропускает уже сделанное.

## 2. Вход в Claude Code (≈3 минуты)

```bash
sudo -u claude-worker -i
claude
```

- [ ] В терминале появилась ссылка для входа. Откройте её на телефоне, войдите под своим аккаунтом Pro
- [ ] Вернитесь в терминал, Claude Code отвечает на простой вопрос (например, «привет»)
- [ ] Выход из Claude: `/exit`, затем `exit` из пользователя `claude-worker`

## 3. Telegram (≈2 минуты)

```bash
nano /srv/mytracker/server/.env
```

Заполните:
```
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TELEGRAM_OWNER_ID=ваш_числовой_id
```

Сохраните (Ctrl+O, Enter, Ctrl+X), затем:
```bash
systemctl restart mytracker-api
journalctl -u mytracker-api -n 20 --no-pager
```

- [ ] В логах есть строка `API запущен на порту 3001`
- [ ] Напишите боту `/status`. Ответ: «Активных задач нет»

Если бот не отвечает, проверьте, что не настроен webhook для этого бота (его можно сбросить через `https://api.telegram.org/bot<TOKEN>/deleteWebhook`).

## 3b. Mini App (≈5 минут, нужен домен)

Mini App открывается только по HTTPS-адресу, IP и http не подходят.

1. Направьте домен (A-запись) на IP сервера и дождитесь, пока он откроется в браузере по http.
2. На сервере: `sudo certbot --nginx -d ВАШ.ДОМЕН`. Certbot сам настроит HTTPS.
3. В `/srv/mytracker/server/.env` добавьте `TELEGRAM_MINIAPP_URL=https://ВАШ.ДОМЕН`, затем `systemctl restart mytracker-api`.
4. В Telegram откройте бота и нажмите кнопку «Трекер» внизу или отправьте `/app`.

- [ ] Открывается трекер внутри Telegram, вход выполнился сам, без пароля
- [ ] Список задач виден, колонки листаются пальцем

Если на экране «Входим через Telegram…» или ошибка:
- «неверная подпись»: `TELEGRAM_BOT_TOKEN` в `.env` не совпадает с ботом, который открыли
- «Этот аккаунт не имеет доступа»: `TELEGRAM_OWNER_ID` не ваш числовой ID
- «данные устарели»: закройте мини-приложение и откройте снова

## 3c. Управление сервером из Telegram и интерфейса (≈2 минуты)

Раздел «Сервер» и команды `/server`, `/logs`, `/service`, `/deploy` работают после разовой настройки прав:

```bash
sudo bash /srv/mytracker/deploy/ops-setup.sh
```

Скрипт добавляет `claude-worker` в группу `systemd-journal` (чтение журналов) и разрешает ему `sudo` без пароля только на перезапуск `mytracker-api`, `restart/start/stop nginx` и запуск `deploy/update.sh`. Файл правил: `/etc/sudoers.d/mytracker-ops`. Затем перезапускает API.

- [ ] Вкладка «Сервер»: видны ресурсы и состояние сервисов
- [ ] Боту `/server`: пришла сводка
- [ ] «Журнал» у `nginx` показывает строки (если пусто или ошибка прав, перезапустите API ещё раз: группа применяется при старте)

Обновление (`/deploy` или кнопка «Обновить MyTracker»): сервер берёт последнюю версию той ветки, в которой установлен, собирает и перезапускает API. Если сборка или запуск не удались, возвращается прежняя версия, бот пришлёт итог. Служебные файлы лежат в `/srv/mytracker/.ops/`.

## 4. Проект (≈3 минуты)

Сначала заведите проект в CRM: вкладка «Проекты» → «Новый проект». Slug (например `shop-api`) должен совпадать с именем папки репозитория. Задачи создаются только в существующих проектах.


```bash
sudo -u claude-worker git clone https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПО.git /srv/repos/тестовый_проект
```

Для push нужен доступ на запись. Самый простой путь на первый тест: deploy key с правом записи.

```bash
sudo -u claude-worker ssh-keygen -t ed25519 -N "" -f /home/claude-worker/.ssh/id_ed25519
sudo cat /home/claude-worker/.ssh/id_ed25519.pub
```

Добавьте публичный ключ в репозиторий: Settings → Deploy keys → Allow write access. Затем переключите remote на SSH:

```bash
cd /srv/repos/тестовый_проект
sudo -u claude-worker git remote set-url origin git@github.com:ВАШ_ЛОГИН/ВАШ_РЕПО.git
```

- [ ] `sudo -u claude-worker git -C /srv/repos/тестовый_проект fetch` проходит без ошибок
- [ ] В репозитории есть `CLAUDE.md` или хотя бы `README`. Claude будет работать от этих правил

## 5. Smoke-тест (≈1 минута)

С сервера:
```bash
cd /srv/mytracker
PASSWORD='пароль_из_шага_1' ./scripts/smoke.sh
```

- [ ] В конце: `Итог: успешно ..., с ошибками 0` (все строки с `OK`, ни одной `FAIL`)

Тест создаёт одну тестовую задачу в проекте `smoke`. Её можно потом удалить прямо из базы или оставить.

## 6. Первая реальная задача (≈15 минут)

Откройте веб-интерфейс по адресу `http://IP_СЕРВЕРА` (или по домену, если настроили HTTPS) либо Telegram.

Через Telegram:
1. `/new slug_проекта Добавить строку README с датой теста`
2. Бот ответит с ID задачи. Скопируйте его.
3. `/ready ID`
4. `/run ID`
5. Ждите уведомления (обычно 1–5 минут).

Через веб-интерфейс:
1. «Новая задача»: проект, заголовок, один критерий приёмки
2. Откройте карточку, «→ Готово к работе», затем «Запустить в Claude»
3. «Показать diff» после перехода в «На проверке»

- [ ] Задача перешла в «На проверке» или «Ошибка»
- [ ] Пришло уведомление в Telegram
- [ ] На GitHub появилась ветка `task/<id>`
- [ ] Diff показывает изменения, которые ожидали

Если статус «Ошибка», прочитайте комментарий и запуск в карточке задачи, там будет текст ошибки.

## 7. Проверка, что всё под контролем

- [ ] В main ничего не попало: `git -C /srv/repos/тестовый_проект log main --oneline -n 3`
- [ ] Стоимость записана: `curl -s -H "Authorization: Bearer ТОКЕН" http://127.0.0.1:3001/api/stats/costs`
- [ ] Бэкап работает: `sudo /srv/mytracker/deploy/backup-mongo.sh` (появился файл в `/srv/backups/mytracker`)
- [ ] Вложения копируются: `sudo /srv/mytracker/deploy/backup-minio.sh` (появились файлы в `/srv/backups/mytracker/minio`)
- [ ] Архив читается: `sudo /srv/mytracker/deploy/restore-mongo.sh verify <файл из /srv/backups/mytracker>`. Рабочая база не трогается, в конце выводится число документов
- [ ] Здоровье сервисов: `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3001/api/health`. Ответ 200 — всё в норме, 503 — что-то не работает. Подробности (очередь, зависшие запуски) видны владельцу в «Настройках» → «Состояние» или в `/api/health/details` с токеном

### Восстановление после потери данных
1. Остановите API: `sudo systemctl stop mytracker-api`.
2. Выберите последний архив, который проходит `verify`.
3. Восстановите: `sudo /srv/mytracker/deploy/restore-mongo.sh restore <файл> --yes`. Команда заменяет базу `mytracker`.
4. Вложения: скопируйте каталог `/srv/backups/mytracker/minio` обратно в бакет через `mc mirror` (см. комментарий в `backup-minio.sh`).
5. Запустите API: `sudo systemctl start mytracker-api`, проверьте `/api/health`.

## Если что-то сломалось

| Симптом | Что проверить |
|---|---|
| API не стартует | `journalctl -u mytracker-api -n 50 --no-pager`. Чаще всего неверный `MONGO_URL` или не запущен контейнер: `cd /srv/mytracker && docker compose ps` |
| Вход в трекер не проходит | Пароль в `server/.env` (`ADMIN_PASSWORD`), после правки `systemctl restart mytracker-api` |
| Задача сразу в «Ошибка» с текстом про git | Нет `origin/main` в репозитории проекта, или нет прав на push (deploy key) |
| «Ошибка» с текстом про авторизацию Claude | Снова выполните шаг 2 под `claude-worker` |
| Раздел «Сервер»: «нет прав на sudo» | Выполните `sudo bash /srv/mytracker/deploy/ops-setup.sh` |
| Бот молчит | `journalctl -u mytracker-api -n 50`, ищите строки `Telegram poll`. Проверьте токен и `TELEGRAM_OWNER_ID` |
| Задача вернулась в «Готово к работе» с упоминанием лимита | Это ожидаемо: лимит Pro исчерпан. Запустите позже. Если сообщение лимита не распознано, пришлите текст из лога, добавим шаблон |
| Запуск «не начинается» | Задача может стоять в очереди, если по этому проекту уже работает другая. Смотрите `/status` |

## Что записать себе после первого прогона

- Сколько заняла задача и какой была стоимость (`costUsd` в запуске)
- Что Claude сделал не так, и что дописать в `CLAUDE.md` или skill
- Какой текст был у сообщения о лимите, если он появился

Эти три пункта дают основу для следующей итерации.
