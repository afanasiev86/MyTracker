# UAT-стенды

Кратко: результат задач попадает в ветку UAT, а проект открывается на отдельном адресе `https://<код проекта>.<домен>`, закрытом общим логином. Ветки UAT и приёмка: `docs/architecture/run-pipeline.md:L21#Рабочая копия`.

## Что готово
Подготовка сервера и открытие адреса. Сборка и запуск приложения проекта, показ ссылки и статуса в карточке задачи, skill `deploy-uat` ещё не сделаны.

## Как устроено
1. Сервер настраивается один раз скриптом `deploy/uat-setup.sh` (пошагово: `docs/RUNBOOK.md:L98#3d. UAT-стенды: настройка сервера (≈5 минут, один раз)`). Нужна DNS-запись `A *` на IP сервера.
2. Домен берётся из `UAT_DOMAIN` (`server/src/config.js:L25@UAT_DOMAIN`). Без него стенды выключены.
3. Адрес стенда: `server/src/services/uat/standHost.js:L9-15#standHost`. Имя проекта должно быть меткой DNS (до 63 символов, латиница, цифры, дефис) и не из списка зарезервированных (`www`, `api`, `tracker` и др.). Тот же шаблон проверяет `deploy/uat-expose.sh`.
4. Порт стенда выдаётся проекту один раз (поле `Project.uatPort`) и больше не меняется: `server/src/services/uat/ports.js:L8-14#pickPort`, диапазон 4100–4999.
5. `server/src/services/uat/ensureStand.js:L38-42#ensureStand` выдаёт порт и запускает через sudo `/usr/local/sbin/uat-expose <код> <порт>`. Выдача портов идёт по одному, чтобы два проекта не получили один порт.
6. `deploy/uat-expose.sh` (root-копия в `/usr/local/sbin`): проверяет аргументы, при первом запуске выпускает сертификат Let's Encrypt для `<код>.<домен>` (`certbot certonly --nginx`, HTTP-01, API reg.ru не нужен) и пишет `/etc/nginx/conf.d/uat-<код>.conf`: редирект на HTTPS, `auth_basic` с файлом `/etc/nginx/uat.htpasswd`, проксирование на `127.0.0.1:<порт>` с поддержкой WebSocket. Если nginx не принял правило, оно удаляется. Повторный запуск безопасен.

## Ошибки и граничные случаи
- Домен и почту скрипт берёт из `/etc/mytracker-uat.conf` (пишет `uat-setup.sh`, принадлежит root), а не из аргументов: вызывающий процесс без привилегий их не подменит.
- Нет sudo-права: ошибка с подсказкой выполнить `deploy/uat-setup.sh`.
- Сертификат не выпускается, если DNS `*` ещё не указывает на сервер.
- `uat-setup.sh` добавляет `default_server` с отказом (`return 444`, `ssl_reject_handshake`). Если `default_server` уже объявлен в другом файле nginx, скрипт откатывает изменение и сообщает об этом.
- Лимиты Let's Encrypt на число сертификатов для одного домена достаточны для десятков проектов (точное число в этом документе не проверялось).

## Тесты
`server/test/uatStand.test.js` (адрес, порты, `ensureStand`). Скрипты проверены вручную в контейнерах: проверка аргументов, генерация правила, `nginx -t` на настоящем nginx; реальный выпуск сертификата и sudo на VPS не проверялись.
