# Функции: клиенты, проекты, вход и ошибки API

## Клиенты и проекты
Маршруты: `server/src/routes/clients/patchClient.js:L5-14#patchClient`, `server/src/routes/projects/deleteProject.js:L5-15#deleteProject`. Удаление проекта запрещено, если есть задачи (409). Формы в интерфейсе: `client/src/components/Projects.jsx`, `client/src/components/Clients.jsx`.
- Код проекта (slug) при создании строится сервером из названия: `server/src/services/projects/slug.js:L24-30#uniqueSlug` (кириллица в латиницу, занятый код получает суффикс `-2`, чужая папка в `REPOS_DIR` не подхватывается). В форме нового проекта поля кода нет, в карточке существующего код только показывается: `client/src/components/project/SlugField.jsx`.
- Клонирование: `server/src/services/projects/repo.js:L25-48#ensureRepo` клонирует `repoUrl` в `REPOS_DIR/<код>` при создании и при сохранении, если папки нет. Допустимы только `https://` и `git@host:путь`, локальные пути и `ext::` отклоняются (`isRepoUrl`), ожидание не больше 55 с. Итог приходит в ответе как `repo.status` (`none`, `exists`, `cloned`, `failed` и `error`); при `failed` проект всё равно сохранён.
- Режим коммитов: флажок «Коммитить сразу в эту ветку» (`commitToBase`, поле формы `client/src/components/ProjectForm.jsx`) отправляет результат задач прямо в «Основную ветку» проекта. Подробности и поведение при конфликте: [run-pipeline](docs/architecture/run-pipeline.md#Рабочая копия).
- Синхронизация с GitHub: `server/src/services/projects/githubSync.js:L18-42#syncWithGithub`, вызовы API в `server/src/services/github/repos.js:L46-54#createRepo`. Включается, если задан токен GitHub: в «Настройках» (карточка «GitHub») или в `GITHUB_TOKEN` на сервере; токен из «Настроек» важнее. Без токена `github.status` = `disabled`, остальное работает как раньше. CRM → GitHub: проект без ссылки получает приватный репозиторий с именем-кодом проекта, описание уходит в описание репозитория, статус «Завершён» архивирует его, другой статус снимает архивацию. GitHub → CRM: при смене ссылки и по кнопке «Синхронизировать с GitHub» (`POST /api/projects/:id/sync-github`, `server/src/routes/projects/syncProject.js:L7-16#syncProject`) подтягивается основная ветка, а пустое описание заполняется из репозитория. Удаление проекта в CRM репозиторий на GitHub не трогает. Итог приходит в ответе как `github.status` (`disabled`, `none`, `created`, `synced`, `failed` и `error`); при `failed` проект всё равно сохранён.
- Токен: `server/src/services/github/connect.js:L6-10#connectGithub` проверяет его запросом `GET /user` до сохранения, хранит в `Settings` зашифрованным (`server/src/services/telegram/secretBox.js`, ключ из `JWT_SECRET`) и наружу не отдаёт, только логин аккаунта. Маршруты `GET/PUT/DELETE /api/github` (`server/src/routes/github.js`), карточка в интерфейсе `client/src/components/GithubSettings.jsx`.
- Git с токеном: клонирование (`server/src/services/projects/repo.js:L25-48#ensureRepo`) и все вызовы git воркера (`server/src/worker/git.js:L9-15#git`) получают токен GitHub по `https://github.com` через `GIT_ASKPASS`: `server/src/worker/env.js:L12-20#gitEnv`, скрипт `deploy/git-askpass.sh` (отдаёт токен только для хоста GitHub). Токен не попадает в аргументы и адреса. Из окружения Claude, проверок проекта и git убираются секреты сервера (база, JWT, пароль входа, токены Telegram и GitHub): `server/src/worker/env.js:L26-30#childEnv`, список `server/src/config.js:L30@SECRET_ENV_KEYS`. Токен GitHub получает только процесс git. Это закрывает чтение секретов через переменные окружения, но не файл `server/.env`: см. раздел «Что видит Claude» в [RUNBOOK](docs/RUNBOOK.md#Что видит Claude). При отказе в доступе ошибка дополняется подсказкой: `server/src/worker/env.js:L34-38#gitAccessHint`. Для SSH-адресов по-прежнему нужен ключ сервера.
- Список репозиториев для выбора в форме: `GET /api/github/repos` (`server/src/routes/github/listRepos.js:L4-11#listGithubRepos`), без токена возвращает `enabled: false`. В форме `client/src/components/ProjectForm.jsx` поле репозитория подсказывает репозитории аккаунта, ссылку можно ввести и вручную.

Единый формат `{ error }`: errorHandler (`docs/functions/server/http/errorHandler.md:L13#Алгоритм`). Сборка приложения: createApp (`docs/functions/server/http/createApp.md:L13#Алгоритм`).

## Хранилище вложений
Файлы вложений лежат на диске сервера, выбора хранилища нет. Подробно о вложениях: [tasks-and-runs](docs/features/tasks-and-runs.md#Вложения).
