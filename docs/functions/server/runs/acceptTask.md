# acceptTask

## Назначение
Принимает результат проверки: задача переходит из «На проверке» в «Принято». Если результат лежит в ветке UAT, перед этим коммиты задачи переносятся в основную ветку.

## Где объявлено
`server/src/services/runs/acceptTask.js:L9-29#acceptTask`

## Вход и выход
- Вход: `task`.
- Выход: `{ task }` или `{ error }`: задача не на проверке, нет сохранённых коммитов или перенос в основную ветку не удался.

## Алгоритм
1. Проверяет статус: `server/src/services/runs/acceptTask.js:L11@Принять можно только задачу на проверке`.
2. Если ветка результата (`task.branch`) не совпадает с основной, переносит `task.commits` в основную ветку: `server/src/services/runs/acceptTask.js:L19@promoteToBase(repo`. Подробности: `docs/architecture/run-pipeline.md:L29#Приёмка: из UAT в основную ветку`.
3. Ставит статус `done` и сохраняет: `server/src/services/runs/acceptTask.js:L26@task.status = 'done';`.

## Ошибки и граничные случаи
- При конфликте или отказе GitHub задача остаётся «На проверке», в ответе причина. Статус «Ошибка» не ставится: исправление Claude начинается от ветки UAT и конфликт с основной веткой не решает.
- Задача, у которой коммитов нет (старый запуск до перехода на UAT), не принимается: перенос не пытается угадывать, что вливать.
- Если результат уже в основной ветке (проект пушит сразу в ПРОД), меняется только статус.
- Вызывается из бота и из `PATCH /api/tasks/:id` при переходе `review → done`: `server/src/services/tasks/patchTask.js:L29@acceptTask(task)`.
