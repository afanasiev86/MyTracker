# enqueue

## Назначение
Очередь запусков по ключу (проекту): задачи одного репозитория идут по одной, разные проекты работают параллельно.

## Где объявлено
`server/src/worker/queue.js:L5-15#enqueue`

## Вход и выход
- Вход: `key` (slug проекта), `job` (функция, возвращающая промис).
- Выход: промис, который завершится после выполнения задания. Ошибки задания логируются и не выбрасываются наружу.

## Алгоритм
1. Берёт хвост цепочки проекта или уже выполненный промис: `server/src/worker/queue.js:L6@const prev = chains.get(key) ?? Promise.resolve();`.
2. Добавляет задание в конец цепочки и гасит ошибку, чтобы очередь не остановилась: `server/src/worker/queue.js:L9@.catch((err) => console.error`.
3. Запоминает новый хвост и удаляет запись, когда очередь опустела: `server/src/worker/queue.js:L12@if (chains.get(key) === next) chains.delete(key);`.

## Ошибки и граничные случаи
- Очередь только в памяти. Если сервер перезапустить, задания из очереди пропадут. Поэтому при старте `server/src/index.js:L20@Задачи, которые были в работе` помечает их как ошибку.
- Очередь не ограничена по длине. Для личного трекера это приемлемо.
