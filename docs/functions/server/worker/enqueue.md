# enqueue

## Назначение
Очередь запусков по ключу (проекту): задачи одного репозитория идут по одной, разные проекты работают параллельно. Внутри проекта срочные задачи (`priority: high`) уходят вперёд обычных и низких. При одинаковом приоритете порядок поступления сохраняется.

## Где объявлено
`server/src/worker/queue.js:L14-25#enqueue`

## Вход и выход
- Вход: `key` (slug проекта), `job` (функция, возвращающая промис), `{ priority }` (`high`, `normal`, `low`; по умолчанию `normal`).
- Выход: промис, который завершится после выполнения задания. Ошибки задания логируются и не выбрасываются наружу.

## Алгоритм
1. Берёт очередь проекта или создаёт пустую: `server/src/worker/queue.js:L15@let queue = queues.get(key);`.
2. Кладёт задание в очередь с рангом приоритета и сортирует по рангу, затем по номеру поступления: `server/src/worker/queue.js:L22@queue.items.sort(`.
3. Запускает следующее задание, если проект ничего не выполняет: `server/src/worker/queue.js:L28-45#drain`.
4. После задания снимает флаг занятости, сообщает промису и снова запускает `drain`. Ошибка логируется: `server/src/worker/queue.js:L39@.catch((err) => console.error`.

## Ошибки и граничные случаи
- Приоритет меняется только при постановке в очередь. Если изменить приоритет задачи, уже стоящей в очереди, он не применится до следующего запуска.
- Очередь только в памяти. Если сервер перезапустить, задания из очереди пропадут. Поэтому при старте `server/src/index.js:L20@Задачи, которые были в работе` помечает их как ошибку.
- Очередь не ограничена по длине. Для личного трекера это приемлемо.
